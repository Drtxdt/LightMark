## 1. 结论与审计边界

**当前不建议发布。已在隔离浏览器中复现两项内容正确性问题：末行重复、同段第二个公式替换范围错误。**

最小复现结果：

| 输入与操作 | 预期 | 实际 |
|---|---|---|
| 无末尾换行的 `abc`，可视化模式末尾输入 `d`，切回源码 | `abcd` | `abcdabc` |
| `A $x$ B`，可视化模式末尾输入 ` $y$`，退出公式并切回源码 | `A $x$ B $y$` | `A $x$ B$y$$`，无末尾换行时还叠加原文重复 |

这两项已有实际行为和相关代码证据。**原生桌面保存、关闭、重开后的磁盘结果尚未验证**，不能把浏览器复现扩大为已完成桌面闭环测试。

本轮没有修改业务代码、测试、依赖、锁文件或项目配置。开始和结束时工作区均干净。已有检查使用其临时测试目录；浏览器只使用新建的未命名审计文档。临时浏览器与开发服务已关闭。

已确认的产品决定：

- 本轮以 Windows 桌面版为发布验收平台；其他平台单列后续。
- 无操作保存要求字节不变；编辑时精确保留未编辑语法范围。
- 跨模式连续撤销。
- 公式 Escape 保持提交退出语义；补全打开时先关闭补全。
- 视觉调整先提交设计方向，不立即整体换主题或布局。

## 2. 现状与架构地图

### 文档与状态链路

```text
Rust 文件读取
    ↓
标签页 content / 全局活动页投影
    ↓
Tiptap / ProseMirror        CodeMirror
可视化文档与 NodeView      源码文档与独立历史
    ↓                         ↓
revision、dirty、派生信息
    ↓
DocumentSessionAdapter.flushPendingEdits / snapshot
    ↓
标签页 Markdown 快照
    ↓
保存 / 草稿 / 模式切换 / 导出 / 工作区索引
    ↓
Rust 文件、草稿及 SQLite 服务
```

主要特征：

- 技术栈为 Vue 3、TypeScript、Vite、Tailwind、Tauri 2、Rust。
- 可视化编辑使用 Tiptap 3/ProseMirror；源码使用 CodeMirror 6；Markdown 渲染使用 markdown-it，HTML 转 Markdown 使用 Turndown。
- 公式为自定义 NodeView：行内使用独立 `contenteditable`，块公式使用 `textarea`，KaTeX 负责渲染。
- 公式编辑同时存在 DOM 文本、NodeView 局部变量和 ProseMirror 属性；保存前通过待提交注册表刷新。
- 性能重构把逐次输入的全文同步改为 revision、派生状态和按需快照。WYSIWYG 快照以不可变节点为缓存键，后台快照可让出主线程。
- 源码保真目前主要依赖**顶层块身份与源码范围**，不能满足已确认的“顶层块内部未编辑范围也精确保留”契约。
- 模式切换会生成快照、捕获位置，再销毁并重建编辑组件。位置有恢复机制，普通撤销历史没有文档级连续性。
- 工作区索引使用 Rust/SQLite；源码公式诊断使用 Worker；大纲、查找和高亮有增量处理。
- 公式 IntersectionObserver 用于延迟首次显示，`rootMargin` 为 300px；不能因此推断公式编辑器发生虚拟化卸载。
- 大文件是独立实现：**文件大小达到 `5 × 1024 × 1024` 字节即进入**，并非 README 所写的严格“大于 5MB”。采用分块读取、块级文本编辑和渲染缓存，不提供完整 Tiptap 编辑能力。
- 自动保存默认关闭；开启后保存到私有草稿目录，不直接覆盖原文件。

## 3. 按风险排序的问题清单

状态严格区分：**已实际复现、有代码证据但未运行验证、待验证假设、未实现、当前环境无法验证**。严重程度与根因可信度分开评估。

### LM-001｜P0，阻止发布：无末尾换行时，编辑后重复原始末行

**状态：已实际复现，浏览器开发环境。**

- **步骤：**源码输入 `abc`，不加末尾换行；切可视化，在末尾输入 `d`；切回源码。
- **预期：**`abcd`。
- **实际：**`abcdabc`。
- **对照：**初始内容带末尾换行时，同样操作得到 `abcd`，未观察到重复。
- **影响：**序列化结果已包含额外内容；后续保存存在持久化错误内容风险。
- **代码：**[markdownTopLevelSourceBlocks](/E:/my_code/LightMark/src/utils/markdown.ts:80)、[combinePreservedSourceBlocks](/E:/my_code/LightMark/src/editor/sourcePreservation.ts:27)。
- **根因判断：高可信。**`toLine` 是排他行号，但被截断到最后一个已有行首。单行无换行文档的块正文变成空串，原文被归为 separator；替换块后又拼回原文。
- **历史证据：**相关范围计算由 `91ed6d3` 引入。
- **缺失验证：**原生保存重开、多行末块、删除末块、CRLF/BOM、列表/表格末块、撤销重做。

### LM-002｜P1，阻止发布：已有原子节点后的公式替换范围错误

**状态：已实际复现，浏览器开发环境。**

- **步骤：**源码输入 `A $x$ B`；切可视化，定位段尾，输入 ` $y$`；Escape，切回源码。
- **预期：**`A $x$ B $y$`。
- **实际：**`A $x$ B$y$$`；第二公式前空格被吃掉，尾部多出 `$`。
- **对照：**补上末尾换行后仍复现，已与 LM-001 分离。
- **影响：**替换错误字符范围，选区定位随之不可信。
- **代码：**[InlineMath.appendTransaction](/E:/my_code/LightMark/src/extensions/MathNodes.ts:103)。
- **根因判断：高可信。**对 `node.textContent` 匹配所得偏移，直接加到 ProseMirror 位置；前面的原子节点占文档位置，却不等价占用纯文本长度。
- **缺失验证：**逐键输入、中文 IME、多个原子节点、图片/HTML 节点前置、列表/表格、撤销和原生桌面。
- **归因限制：**重构前已有同类换算，不能未经历史运行比较就称为重构新增回归。

### LM-003｜P1，发布前必须定界：写盘完成后可能清除更新的脏状态

**状态：有代码证据但未运行验证。**

- **验证步骤：**隔离文件触发保存，在写入完成前继续输入或切换标签；读取磁盘、缓冲和脏状态。
- **预期：**只确认指定文档、指定 revision 已保存；新输入继续保持未保存。
- **代码实际：**[saveCurrentFileImpl](/E:/my_code/LightMark/src/stores/appStore.ts:1104) 在多个 `await` 后继续读写活动页全局状态，并直接设置 `appStore.isDirty = false`，随后清理活动草稿。
- **根因判断：中高可信。**快照生成阶段的 revision 校验没有覆盖完整写盘完成阶段。
- **缺失验证：**确定性慢写入、连续保存、保存对话框期间切页、后台草稿与保存交叉执行。

### LM-004｜P1，发布前必须定界：局部编辑缓冲与关闭/草稿判定不一致

**状态：有代码证据但未运行验证。**

- **验证步骤：**打开已保存文档，仅编辑公式或大文件块，不主动失焦；立即保存、关闭窗口或等待草稿周期。

- **代码：**[MathNodes](/E:/my_code/LightMark/src/extensions/MathNodes.ts:512)、[关闭判定](/E:/my_code/LightMark/src/App.vue:190)、[草稿入口](/E:/my_code/LightMark/src/stores/draftStore.ts:59)、[大文件提交](/E:/my_code/LightMark/src/components/editor/LargeMarkdownEditor.vue:224)。
- **根因判断：中等。**存在多份未提交状态，但最终结果受失焦、组合结束和窗口事件顺序影响。

- **预期：**无操作字节不变，未编辑范围不变，失败后确有可用恢复出口。
