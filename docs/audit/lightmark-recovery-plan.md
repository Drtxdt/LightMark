# 文档二：LightMark 分阶段恢复计划

拟保存为：`docs/audit/lightmark-recovery-plan.md`

## 1. 执行原则与发布门槛

所有代码、测试、性能探针和构建脚本修改均由 **`luna_coder / gpt-5.6-luna / max`** 完成。每次派单检查运行记录；配置不受支持时停止并报告，不静默降级。

主负责人负责问题复核、设计裁定、关键 diff 审查及独立验收。同一编辑器核心模块串行修改。功能恢复、性能优化、视觉调整分别提交。

发布门槛：

- LM-001、LM-002 必须修复。
- LM-003～LM-007 必须完成定界；确认的数据丢失、静默改写、错误选区或不可恢复问题必须修复。
- LM-008 按已确认的跨模式撤销契约验收。
- LM-011 若发现越权执行或资源访问，阻止发布。
- 测试失败须有明确修复或经审查的契约更新，不能删除检查掩盖问题。
- 未验证的 Windows 关键文件/IME路径不能以编译通过替代验收。

相对工作量：S＝局部；M＝跨少量模块；L＝跨状态链路；XL＝需分阶段交付。不据此承诺日历工期。

## 2. 可独立验收的工作包

### WP-01｜修复无末尾换行导致的内容重复

- **目标/问题：**消除 LM-001；最高优先级。
- **依赖：**无；开始前固定提交和工作区状态。
- **修改边界：**源码块范围计算、拼接及对应回归测试；不改引擎、历史、主题或性能策略。
- **方案：**修正排他末端行号到源码偏移的转换；明确 EOF 边界；保证正文和 separator 的划分不重叠、不遗漏。
- **验证：**先新增失败用例，再修复；覆盖 `abc → abcd`、有无末尾换行、LF/CRLF/BOM、多行末块、块插删。执行真实可视化往返及隔离桌面保存重开。
- **性能约束：**保持线性范围提取，不在每次输入新增全文序列化。
- **风险/回滚：**可能影响末块分隔；独立提交可回退，但回退后仍禁止发布问题版本，不自动改写用户文档。
- **工作量/不确定性：**S～M，低至中。

### WP-02｜修复同段原子节点后的公式位置映射

- **目标/问题：**消除 LM-002。
- **依赖：**WP-01，避免保真错误污染公式断言。
- **修改边界：**公式匹配范围、节点位置映射及专项测试。
- **方案：**显式建立文本片段与 ProseMirror 位置对应；原子节点作为边界处理，不以扁平 `textContent` 偏移直接替换文档。
- **验证：**同段 1/2/多个公式，前置图片或 HTML、左右输入、列表/表格、复制粘贴、一次撤销重做；核对精确源码和选区。
- **性能约束：**保留局部扫描，不退回每键全篇遍历。
- **风险/回滚：**可能影响自动识别边界；独立回退本包，保留失败用例。
- **工作量/不确定性：**M，中。

### WP-03｜建立隔离原生证据与可信回归入口

- **目标/问题：**补齐 LM-003～LM-009、LM-011 的验证条件。
- **依赖：**无；可与 WP-01 的局部修复并行准备，但不并发修改核心。
- **修改边界：**测试、夹具、测试启动器及仅测试启用的探针；不改变产品正常行为。
- **方案：**固定测试配置和笔记根目录；测试不得挂接任意活动页。归档提交、构建、运行时、机器、夹具哈希和原始结果。
- **验证：**确认没有访问真实笔记；故意失败时有结果记录和资源释放；将表格旧断言与实际产品契约核对后纳入统一入口。
- **性能约束：**探针默认关闭；记录探针本身的影响。
- **风险/回滚：**自动化可能污染状态；独立测试目录与配置，回滚仅移除测试接入。
- **工作量/不确定性：**M～L，中高，取决于 WebView2 控制能力。

### WP-04｜收敛保存、草稿和大文件提交边界

- **目标/问题：**处理 LM-003、LM-004、LM-006。
- **依赖：**WP-03；内部拆为普通保存、大文件提交、磁盘替换三个独立提交。
- **修改边界：**文档会话刷新、保存协调、草稿及 Rust 文件服务。
- **方案：**保存开始固定文档身份、路径、revision 和快照；成功回执只确认对应版本。关闭/草稿先识别并刷新局部缓冲；大文件等待编辑队列。统一普通/大文件冲突检查，消除固定临时名竞争，明确中断后的恢复步骤。
- **验证：**慢写时继续输入、切页、连续保存、组合输入、外部修改、写入失败、替换各阶段中断；检查磁盘、缓冲、dirty 和草稿一致性。
- **性能约束：**版本或内容校验放在保存边界，不进入输入热路径；大文件保持有界内存。
- **风险/回滚：**文件事务变更风险高；不迁移真实笔记，保留恢复副本；各提交独立回退。
- **工作量/不确定性：**L，高；复现结果决定局部修复是否足够。

### WP-05｜兑现精细 Markdown 保真与失败恢复

- **目标/问题：**处理 LM-005，并防止 LM-001 类问题再发。
- **依赖：**WP-01、WP-03。
- **修改边界：**源码封装、变更范围映射、序列化及恢复入口。
- **方案：**保留原始换行/BOM信息；基于有版本的源码范围应用变更，未编辑范围复用原文。模式切换不产生格式化。映射失败时保留编辑缓冲，提供不重复依赖失败序列化器的恢复副本路径。
- **验证：**无操作字节比较；列表/表格只改一处、未知语法、Frontmatter、相对路径、混合换行、空文件、非 UTF-8 拒绝覆盖；故意破坏映射验证可恢复性。
- **性能约束：**测量映射成本与内存；不在输入时无条件生成整篇 Markdown。
- **风险/回滚：**不能假定所有扩展都有精确逆映射；无法安全映射时阻止覆盖并保留数据，不能静默整块规范化。独立回退，不转换磁盘格式。
- **工作量/不确定性：**L～XL，高。

### WP-06｜公式生命周期、IME与焦点闭环

- **目标/问题：**处理 LM-007，并复验公式相关 LM-004。
- **依赖：**WP-02、WP-03；与修改 MathNodes 的工作串行。
- **修改边界：**公式 NodeView、补全和会话刷新。
- **方案：**区分显示、编辑、组合输入、提交和销毁；规定局部值与节点属性的同步方向。组合期快捷键不抢占 IME；销毁和取消不能提交到失效位置。保留已确认的 Escape 与块公式多行语义。
- **验证：**完整公式专项矩阵，包括非法公式、补全接受/取消、边界删除、跨公式选择、Home/End、滚动返回、列表/表格及模式切换。
- **性能约束：**同时测公式密集文档；不以固定延时、吞异常或永久关闭懒渲染修复。
- **风险/回滚：**焦点与浏览器事件顺序敏感；每个状态转换独立留证，回退对应提交。
- **工作量/不确定性：**M～L，高。

### WP-07｜建立文档级连续撤销

- **目标/问题：**实现 LM-008 的已确认契约。
- **依赖：**WP-05、WP-06。
- **修改边界：**文档历史协调及两个编辑器适配器；不更换编辑器。
- **方案：**历史随文档生命周期保留；记录内容变更与前后选区书签，模式切换只替换视图。展示 transaction 不进入内容历史，格式化与公式提交有明确撤销边界，避免两套历史重复消费同一操作。
- **接口：**文档级 undo/redo 能力、版本化变更及选区映射；外部重载必须形成明确恢复边界。
- **验证：**可视化→源码→可视化连续撤销重做，公式、表格、格式化、分屏与跨标签隔离；保存后继续撤销再保存。
- **性能约束：**测历史增长与长文档内存；不默认每键存全文快照。
- **风险/回滚：**属于针对性状态重构；先交付设计和失败用例，由主负责人审查再实现。独立回退，不能混入性能优化。
- **工作量/不确定性：**L～XL，高。

### WP-08｜建立性能基线，再做有依据的优化

- **目标/问题：**补齐 LM-009 的性能证据。
- **依赖：**WP-03；最终基线在核心正确性修复后重采。
- **修改边界：**先仅测量脚本和夹具；具体优化另开工作包。
- **方案：**固定发布构建、机器和运行时；六类负载，5MiB−1、5MiB、5MiB+1 阈值用例。分别测冷/热启动、打开、输入到绘制、粘贴、切模式、滚动、公式及内存。
- **统计：**启动各先采 10 次；交互每负载至少 3 轮、每轮 100 次独立操作，保留原始样本，报告中位数/P95/最大值及限制，不用少量样本宣称稳定 P99。
- **验证：**每轮同时检查内容、选区和历史；区分同步调用、下一帧与真实呈现测量口径。
- **性能约束：**基于测量波动、任务体验和瓶颈提出预算，经审查后锁定；不直接继承 16ms。
- **风险/回滚：**测量工具可能改变时序；保留无探针对照。优化需单独提交、单独回退。
- **工作量/不确定性：**L，高。

### WP-09｜视觉一致性与任务 UX

- **目标/问题：**处理 LM-010。
- **依赖：**设计可提前；实现需设计确认，核心交互稳定后验收。
- **修改边界：**设计 token、组件样式和必要可访问属性；不改编辑状态链路。
- **方案：**基于现有中性灰/蓝色方向，统一 surface、text、border、accent、focus、selection、error、disabled，以及字体、间距、圆角、弹层层级；提交浅深主题对照，不默认替换现有图标或主题开关。
- **验证：**新建保存、公式修改、图片粘贴、查找、切模式、恢复误操作、重开任务；默认/最小窗口与三档 Windows 缩放，实测对比和键盘焦点。
- **性能约束：**记录布局、重绘和动画影响，不引入持续重排。
- **风险/回滚：**审美偏好与可操作性分开记录；样式提交独立回退。
- **工作量/不确定性：**M，中。

### WP-10｜桌面内容安全边界

- **目标/问题：**定界并处理 LM-011。
- **依赖：**WP-03。
- **修改边界：**渲染过滤、链接/资源解析、Tauri CSP及权限配置。
- **方案：**先以本地夹具确认完整攻击路径；按实际资源需求收敛权限。涉及远程 iframe、本地引用兼容性的产品限制需单独说明，不擅自删除功能。
- **验证：**脚本事件、异常 URL、iframe、SVG、路径逃逸、合法相对图片及导出；验证产品渲染而非只测过滤函数输出。
- **性能约束：**安全校验不能变为每键全篇处理。
- **风险/回滚：**可能阻断合法内容；配置与过滤分别提交。确认漏洞后不得仅为兼容回退到不安全状态。
- **工作量/不确定性：**M～L，高。

### WP-11｜独立发布验收与文档校准

- **目标/问题：**关闭上述问题，统一 README 与证据。
- **依赖：**核心修复、性能基线及安全定界完成。
- **修改边界：**验收材料和发布文档；发现新缺陷另派修复包。
- **方案：**主负责人审查实际 diff，并独立运行固定 Windows 发布构建；证据绑定提交、构建哈希、平台和测试数据。
- **验证：**完整文件闭环、公式专项、IME、历史、错误恢复、安装与实际导出；未实现能力明确标注。
- **性能约束：**满足 WP-08 后续确认的预算，正确性不因优化退化。
- **风险/回滚：**不把既有安装包视为已验证；失败则不发布，回退到经过同样验证的候选版本。
- **工作量/不确定性：**M，中高，取决于发现的新问题。

## 3. 验收矩阵与后续功能边界

公式验收必须逐项覆盖：

- 行内/块：插入、进入、退出、鼠标定位、方向键、Home/End、前后输入、边界删除。
- 跨公式选区、复制粘贴、撤销重做、焦点恢复。
- 补全接受/取消、非法公式、中文组合输入。
- 列表和表格内、模式切换后、滚动返回后、普通与公式密集负载。
- 不适用的大文件可视化行为明确写“不适用”，另测其块文本编辑。

每项证据必须记录：问题编号、夹具、操作、预期、实际、提交/构建、平台、日志或截图、根因可信度和仍缺验证。

分阶段顺序：

1. **阻止发布的问题：**WP-01、WP-02；并行准备 WP-03。
2. **数据与核心体验：**WP-04～WP-07，按核心模块串行集成。
3. **基线、安全和视觉：**WP-08、WP-10；WP-09先设计后实现。
4. **最终验收：**WP-11。

Typora 全功能覆盖、更多 Obsidian 能力、竞品差异化和其他平台扩展不进入当前修复提交。后续候选必须以具体写作任务、兼容性及性能成本提出；本轮没有授权新增功能集合。

当前没有阻塞 WP-01 的产品选择。仍需后续确认的是视觉样稿、实测性能预算，以及安全定界若涉及功能限制时的取舍；这些均有明确审批边界，不交给编码代理自行决定。

**首选 WP-01：修复无末尾换行导致的内容重复。**
