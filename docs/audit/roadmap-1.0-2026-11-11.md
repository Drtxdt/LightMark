# LightMark：从当前工作树到 Windows 1.0

**发布承诺：** 一个普通 Windows 用户从资源管理器打开自己的 Markdown，能用中文连续写作，在可视化与源码间往返，安全保存、恢复，最后带走一份可用的文档。对写作者而言，这比多十个导出格式更能定义“正式版”。

本计划从[四轮审查](release-review-2026-11-11.md)和[本轮验证](evidence/2026-11-11-baseline.json)出发。C1–C5、A1–A3、Q1–Q3 均是审查中的编号。旧 WP04、WP05、WP07、WP08、WP10、WP11 的实现、夹具和失败记录继续使用；进度以当前候选版本实际通过的用户任务认定。

## 1.0 做到哪里

执行进度另记在[首批修复与验收](release-implementation-2026-11-11.md)；下面的排期和退出条件是各里程碑的原始计划。

| 范围 | 公开承诺 | 暂不承诺或降级方式 |
| --- | --- | --- |
| 平台与文件 | 首发建议 Windows 11 x64、WebView2、UTF-8 `.md/.markdown`，含 BOM、混合换行和无末尾换行；文件是用户的，可以交给其他工具 | Windows 10、ARM64、macOS、Linux 各自以真实机器/发行包装好验收再加入。非 UTF-8 明确拒绝覆盖并指引另存，不静默转换。 |
| 普通写作 | 可视化为首选；源码能接手。标题、列表、链接、图片、代码、表格、常用公式都有明确的打开—修改—撤销—保存—重开契约 | 未知语法保留原文；无法证明保真时保留当前编辑状态并给出可用的恢复出口。允许明确只在源码中编辑的语法。 |
| 文档规模 | 现实现于 **5 MiB** 切大文件，**大于 500 MiB** 只读。发布页分别列“完整可视化、源码/分块编辑、只读”实测范围 | 5 MiB 以下也可能有数万段或数千公式。不得把“能打开”宣传成“同样流畅”。超预算走经验证的降级路径，保留位置、历史、数据和原因说明。 |
| 草稿与隐私 | 手动保存写原稿，恢复草稿只入本机私有目录。建议新安装默认开启崩溃保护，允许关；既有用户沿用其选择 | 不做云同步依赖。不自动上传正文、文件名、路径或崩溃材料；用户可预览并主动提供最小诊断信息。 |
| 导出与扩展 | HTML/PDF 作为核心；PNG、CLI 和已通过的 Pandoc 目标明确列出依赖、限制和结果。离线可完成本地编辑与核心工作流 | 不以 17 个格式全保真、第三方插件市场、图床、双链知识库扩张或三平台同时发布作为 1.0 前提。保留能工作的已有功能，不在冻结期扩面。 |

## 节奏、依赖与责任

以下是**建议排期，不是发布日期**。估算假设：1 名编辑器工程师、1 名 Rust/桌面工程师、1 名质量/发布工程师，产品/设计与 Windows 原生验收有人每周投入。若独立开发，同一人仍按这些角色分批工作，先签收红样本再修；把下列并行工作改为串行，按 **6–9 个月**规划。多人约 **16–20 周**得到可发布候选，最终由证据决定是否放行。

关键依赖：候选源可重建 → 原稿完整性与授权 → 核心写作/恢复 → 实机性能与产品承诺收敛 → 同包安装验收 → 分批发布。测试设施、发布签名准备和用户语料征集可提前并行；不要等到 RC 才第一次做升级。

| 时间与里程碑 | 主责 | 要交付的变化 | 阶段退出条件 |
| --- | --- | --- | --- |
| 第 1 周 · M0 可复现基线 | 发布 + 两端维护者 | 盘点 81 个已修改、134 个未跟踪文件及来源；保存源码清单/依赖锁/构建命令，按可审边界形成候选分支。建立失效样本目录、问题表和 PR 流程。记录外部 CI 实际状态。 | 一台干净 Windows runner 不依赖原工作区 `.cache`、`dist` 或未跟踪文件，即可安装锁定依赖、构建、跑检查。失败能下载一份可读报告；候选产物可映射回源码。 |
| 第 2–4 周 · M1 安全写回 | 编辑器 + Rust | 先修 C1/C2，再修 C3；统一新建、附件与导出对覆盖的约束。正常文档/大文件各保留一次真实往返；为保存失败提供保留输入、另存副本或恢复包的可走通路径。 | C1 的两种选择范围、C2 的路径对照、C3 的原串坐标在修复前红、修复后绿；按原稿和独立预期逐字节比较，撤销/重做也通过。正常不同输出和合法图片继续工作。仍有 P0 就停在本里程碑。 |
| 第 5–7 周 · M2 会话、恢复与桌面边界 | Rust + 编辑器，质量复核 | 修 C4/C5；把文件树、索引和监听绑定同一工作区代次。拆开配置读取、空白页创建和持久化；上次好配置可恢复。统一文档所属资源路径，收敛 A3。把关闭保护移到可编辑前或提供等价保障。 | 延迟/乱序、配置截断/写失败、跨分屏同名图的正反例通过；多草稿可逐个恢复，原稿不变。独立配置下异常退出后重开并与最后一次草稿回执比对。离线合法资源工作、未授权资源拒绝；生产包不含 QA 桥。 |
| 第 8–11 周 · M3 每天都能写 | 编辑器 + 产品/设计 | 补齐打开/新建/另存/搜索的键盘路径、文件关联和命令精确匹配；统一保存、草稿、外部修改的提示和下一步。完成中文 IME、剪贴板、缩放、键盘焦点、撤销和源码退路。用三个真实任务校验首用体验。 | 按下文任务逐条用 Windows 实机验收；用户不看说明可从收到 `.md` 到写完保存再打开。计划中支持的 IME/键盘工作流没有丢字或焦点死路；不能支持的语法/模式有可发现的说明。 |
| 第 8–12 周 · M4 性能与规模（并行） | 性能主责 + 编辑器 | 复用已有采样器定位 50k WYS、公式提交、源码头部删除和多范围更新；先量模型、派生状态、DOM、rAF、内存，再决定增量化、延迟求值或进入源码。每次只改一个热点。 | 同机器、同夹具、相同采样协议下保留优化前后原始结果；按下文预算放行承诺区间。预算外路径明确回退且验证字节/选区/历史；没有“加内存上限”式验收。 |
| 第 12–14 周 · M5 功能冻结/Beta | 发布 + 质量 | 从干净来源生成候选包、签名/时间戳、哈希、第三方声明和发布说明。首轮安装/升级演练、旧配置/草稿迁移、离线与缺 Pandoc 行为。邀请小规模中文写作者试用，允许并行保留旧版本和原稿。 | 两套代表性 Windows 环境完成新装、升级、保存重开和卸载；收集到带版本/场景的失败可复现。有明确回滚步骤、支持入口、安装包身份与来源核对。存在已知内容损坏时不对外发 Beta。 |
| 第 15–16 周 · M6 RC | 发布负责人 + 独立验收者 | 冻结版本和候选安装包；在最终包重跑本地文件、崩溃恢复、中文、导出、大文件及边界矩阵。检查升级后回滚是否仍能读笔记与草稿。写用户故障恢复指南。 | 同一个签名安装器、固定源码、可下载的报告，发布门槛表全部有证据或正式缩小支持范围。重打包变更哈希时重做受影响验证。不得用 dev/QA exe 或截图替代安装结果。 |
| 第 17–20 周 · M7 预留与 1.0 投放 | 发布 + 产品 | 仅处理阻断项；小批用户→扩大→正式公开。发布 HTML/PDF、文件大小、外部依赖、平台和恢复边界说明。预演停止分发和热修复。 | 连续两个观察窗口没有未解决的原稿损坏、不可恢复或安装阻断；先验证反馈渠道实际可用。到日历日期但条件未满足，保持 RC 或收窄范围。 |

## 可以立即开始的第一组 PR

| 顺序 | 范围与依赖 | 主审要看到什么 |
| --- | --- | --- |
| 01 | 证据与 CI：重建候选，固定 Node/pnpm/Rust；修复 TEMP 夹具路径比较并保留对照。与功能修复可并行。 | 干净检出，先构建再做 bundle 检查；默认及普通临时目录均有回执。不要降低安全断言来换绿灯。 |
| 02 | C1：先把 `L$x$R`、公式两侧、硬换行和跨 mark 的合法命中加入编辑器测试，再改查找文本分段与端点方向。 | fixture 的手写预期、PM 节点序列、待修版原生失败；修复版原生“查找/替换/撤销/保存/重开”全链路。不要夹带 WYS 组件大拆分。 |
| 03 | C2：GUI 和 CLI 共用后端输出身份检查，已有原稿不能成为输出。可与 02 并行。 | 输入哈希不变，错误在创建输出之前报告；不同合法输出、禁止覆盖、显式覆盖另一文件三组均有实际产物。 |
| 04 | C3：独立修大小写折叠到原串范围的映射，补单次、全部、撤销；不要改变模式未声明的语义。 | `AİBC!` 只替换 B；组合字符、emoji、中文+英文、大小写开关对照。使用手写预期，不能用同一个查找函数生成答案。 |
| 05 | C4：前端工作区代次；与 Rust 索引现有 generation 对接。 | A 慢 B 快、A→B→A、旧错误晚到；文件树、标题、快速打开、标签结果、监听根一致。 |
| 06 | C5：启动错误处理与原子配置写入；读坏只在内存回退。 | 初次安装可用、读坏不写、旧好配置可找回；设置连改和正常退出后最新值正确持久化。 |
| 07 | A2/A3 分成独立评审：先新建/附件排他创建，再做文档资源授权，最后启用生产 CSP。 | 同名并发不会覆盖；合法同目录/经授权父目录图片、KaTeX、Mermaid、导出仍可用。只读越界样本被拒绝；审查配置与 Rust 命令，不仅审 HTML 过滤。 |

每个修复 PR 的说明都给出：触发动作、之前和之后的结果、所属文档/文件、自动证据与未测试的边界。新语法、格式化全仓、UI 换肤不和这些改动合并。

## 写作者的验收合同

| 任务 | 操作与语料 | 判定标准 |
| --- | --- | --- |
| 收到一篇文章 | 从系统“打开方式”、Ctrl+O、最近文件分别打开同一份含中文路径的文章；打开 A 后再打开 B | 冷/热启动都打开预期文件，焦点能直接输入；不用先学工作区。取消对话框不产生空文件，工作区切换不让旧树复活。 |
| 修改一页而不破坏其余内容 | 正常、空、BOM、LF/CRLF/混合、无末尾换行；含列表缩进、引用、代码、表格、脚注、图片、公式和未知语法；单处编辑、来回切换、撤销 | 无操作保存逐字节相同；编辑仅改变预期区间。跨标签/分屏不改错对象；同一段落放多种节点，分别检查节点保留和磁盘文本。 |
| 连续中文写作 | 真实微软拼音，另选一种目标用户常用 IME；组合中按 Enter、Esc、箭头、Ctrl+S，切页与模式；粘贴文本/HTML/图片；键盘完成查找替换 | 候选提交/取消符合输入法习惯，无重字、丢字、串页。粘贴失败留下原输入；撤销一次只撤销该次动作。模拟 composition 事件仅作 PR 快测。 |
| 磁盘竞争与恢复 | 外部工具改写/删除、磁盘写失败、保存等待期继续输入；三份未命名草稿、两份已命名文档、一次异常退出和重启；旧版草稿迁移 | 只有真正写入的版本可标已保存；新输入仍脏。失败可重试、另存或导出恢复材料。恢复默认新文档；手动比对最后回执，不用“没有崩溃”代替验收。 |
| 大文档和资源 | 5 MiB−1/等于/＋1、50/100/500 MiB 和 500 MiB＋1；多行选区、跨分块搜索/替换、超 16 MiB 选区的导出/限制；另一分屏同名相对图片 | 标明适用模式及只读边界；预期支持的修改能保存重开并比对字节。拒绝项给原因及出路，不让用户先改再告知不能保存。 |
| 交稿与日常可达性 | 导出含中文、图片、表格、代码、公式的多页报告；900×600、常用大窗口、100/125/150/200%、深浅主题，纯键盘与讲述人运行关键任务 | 文件能在下游实际打开，内容可读取、尾页完整；故障提示说明下一步。对话框焦点可见，Tab 不逃逸，Enter 执行当前按钮，Esc 返回原焦点。 |

每一行都标目标平台、候选哈希、证据和限制。已有 [Windows 验收矩阵](windows-release-acceptance.md) 的 WIN-F/E/U/X/S/P 编号可以直接复用，不建第二套“全部已完成”表。

## 建议预算与反馈周期

下面的数字是**拟采用的产品目标**。M0 选定至少一台 8 GB 入门机、一台 16 GB 日常机；记录 Windows/WebView2、供电、视口、DPI 和软件版本。M4 用同一夹具和设备校准，只有明确变更支持范围时才能调整预算。

| 指标 | 建议验收线 | 如何解释 |
| --- | --- | --- |
| 普通作者任务 | 10–100 KiB 混合文章，冷启动到可输入 P95 ≤3 s；普通输入到下一次 rAF P95 ≤50 ms，连续操作不可出现 >250 ms 的可重复长停顿 | 记录按键→模型、DOM、rAF，不宣称测到物理屏幕。快速日测和正式测量分开；正式重放沿用固定轮次、原始样本和正确性检查。 |
| 高密度内容 | 若宣称提供完整 WYS，50k 段头部 Enter/Backspace P95 ≤100 ms、公式密集提交 P95 ≤200 ms；30 分钟编辑/撤销/关页后内存不持续上升 | 对照历史 974.1/825.3/540.4 ms；进程树 private bytes 与 JS heap 分开记录。M0 在 8/16 GB 两机建立绝对内存预算；达不到则移出 WYS 承诺区、主动提示并验证降级和恢复。 |
| 恢复保护 | 建议默认保护下，普通文档停止输入后 **10 s 内**有本机恢复点；连续输入每 **30 s 内**至少一次。正文文件只因显式保存策略写入 | 两种节奏分别在脏状态强制结束进程，用草稿最后回执与恢复文本比对。大文件区分已确认编辑与本地待确认输入，单列实测 RPO；关闭保护后给出真实边界，不许承诺零丢字。 |
| 合并反馈 | PR 快检目标 P95 ≤5 分钟、完整合并检查 ≤15 分钟；工作日首次人工反馈 ≤1 个工作日 | 作为团队目标，未声称项目已有此速度。记录首个有用失败的时间、排队与执行分开。单人项目由作者先自审设计，再用自动检查及阶段独立验收补足。 |

**每个 PR**：设计涉及谁的文档、哪条失败路径，先由一名主审确认；再看实现、测试与兼容性。并行运行前端类型/相关行为语料、Rust 相关用例；全量合并检查用 `pnpm install --frozen-lockfile` → `pnpm build` → `pnpm check:all`，Rust 走 `cargo test --manifest-path src-tauri/Cargo.toml --locked`。改变保存、映射、导出或权限的 PR 增加一项对应的真实 Windows WebView 冒烟。异常和重跑都留记录；同一测试反复失稳就指派负责人修，不靠“重跑绿了”放行。

**每夜**：更大混合语料、乱序/失败、时间受控或固定种子的历史回放、50/100/500 MiB 物理夹具、多分屏图片、长写作内存趋势。非产品代码的 release 探针可测诊断版，但保留它与普通包的源码对应和不同二进制身份。合并前检查先反馈最相关的失败；每夜全量用于发现被选择规则漏掉的回归。

**每个候选包**：构建一次，记录 Git 身份、两套依赖锁、WebView2、二进制/安装包 SHA-256、签名和测试夹具版本；安装、迁移、崩溃恢复、导出、卸载用这一个包。在干净系统和上一版用户配置上各走一遍。发布说明分“验证支持、明确降级、未支持”；签名、依赖声明、离线安装前提、恢复步骤、旧包下载和支持渠道都能被用户找到。

## 放行、停止与 1.0 之后

| 关口 | 由谁签收 | 不通过时 |
| --- | --- | --- |
| 原稿与恢复 | 编辑器、Rust、独立验收人 | C1/C2 等 P0 归零；核心路径不允许残留静默内容错误。发现一例可复现的损坏，立即停发；保留样本，提供保护原稿的退路和上一稳定包。 |
| 安全与范围 | 桌面负责人、产品负责人 | 资源授权或生产边界不成立则阻断；必要时关闭可选内容入口并公布限制，不回退到已知不安全策略。 |

投放可按“内部 → 邀请 10–20 位日常写作者 → 更大 Beta → 稳定下载”推进，每批观察至少一个完整的写作、重启、导出周期。反馈只记录有同意的最小信息：版本、模式、大小区间、失败动作；不强求用户上传原稿。维护者保留旧安装包、迁移说明和回滚演练结果；升级前备份配置/草稿格式，不让程序降级变成用户数据降级。
