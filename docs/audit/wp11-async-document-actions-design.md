# WP11 补充修复：异步文档操作的归属

2026-09-08，主负责人设计。对应 LM-014、LM-015、LM-017；目前均有代码证据，未完成延迟生产入口复现。它们属于现有功能正确性，不授权新增功能或合并到视觉/性能提交。

## 共同约束

异步操作开始时固定原始文档对象、文档代次、路径、模式/会话、revision、pending input token 和操作类型。pane 只用于当时的 UI 归属，不能用完成时的活动 pane 找回正文。对当前文档所需的输入 flush 完成后，重新固定内容与版本；保存、导出和插入使用不同的后续语义，不套用一个“版本不变才成功”的布尔值。

快照生成与恢复材料留在已有边界；每键不新增整篇序列化。用户在等待期间编辑、切页、切模式或关闭文档时，旧操作不得覆盖新正文或另一个文档。捕获的设置必须是本操作的不可变值，不能持有完成时会变化的 reactive settings 对象。

## LM-014：导出

生产入口为 `runDocumentExport`。当前在多个 await 后继续读取 `appStore.currentContent/currentFilePath/settings`，公式能力检查与实际输出可能来自不同文档。

导出按固定快照执行：预检查、用户看到的降级说明、资源基准目录、数学编号、样式主题、目标格式和实际输出使用同一份内容及设置。获得快照后继续编辑允许保留新编辑，导出仍输出当时版本；若快照尚未完成时文档身份失效，明确中止。完成反馈标识导出文档/文件，不能让用户误以为另一个活动文档已导出。导出后的打开行为使用本操作设置。

验证先通过实际生产入口暂停快照/降级对话框/资源内联，期间切文档和修改设置，断言完整 export request 的正文、路径、设置一致；再在隔离 Windows 中实际生成 HTML/PDF/PNG，并核对正文及相对图片。前者只能证明协调逻辑，后者才证明真实输出。

## LM-015：格式化预览

生产入口为 `formatCurrentMarkdown`。预览内容与其适用版本一起保留；用户确认时重新核对原始文档、会话、代次、revision、pending token 和预览前的源码。任一变化使原预览过期：不应用旧结果，保留新输入并提示重新生成预览。不能按当前 pane 应用之前的格式化结果。

LM-016 已修正默认按钮抢占 Cancel Enter 的问题，但不等于预览版本竞态已修复。测试分别覆盖取消、确认、对话框期间同文档新输入、换页/分屏、销毁会话、公式局部输入，以及一次撤销恢复格式化前的精确源码。跨模式撤销最终归 WP07 文档历史，不能新造第三套历史。

## LM-017：图片处理与插入

`saveImagesAsMarkdown/saveImageAsset` 以及 WYS/Source 的粘贴和拖放入口，需固定文档资源基准目录与图片处理设置。压缩、读 bytes、落盘都使用这一上下文；同批多图不能部分写到文档 A、部分写到 B。

插入位置使用捕获时有版本的书签。期间发生当前文档编辑时，通过实际 PM transaction mapping / CM changes 映射位置；会话销毁、模式切换或映射失效时不得把旧坐标应用到新 view。是否能在文档对象层继续插入须由明确适配器契约证明，不能用“当前 selection”代替最初意图。

资源已保存但插入无法完成时，保留生成文件并反馈位置，便于用户恢复；不得自动删除或静默吞错误。避免为本包引入覆盖现有资产的写法。真实测试使用独立图片夹具和可控压缩/写入等待，分别验证切页、同页插入前输入、拖放位置、批量两张图、会话销毁及写入失败。原生剪贴板行为需另有 Windows 证据。

## 工作边界与验收

三个问题各独立补丁，先补失败用例再改生产入口。共同纯上下文类型可以复用，具体的导出快照、格式化拒绝过期、图片书签映射必须分别验证。WYS/Source 的 writer 按主负责人锁定顺序接入，不并发修改同一核心文件。

相对工作量：导出 S～M，格式化 M，图片 M～L；主要不确定性是模式/会话销毁后的资源插入语义。性能约束为沿用现有输入热路径，仅在实际操作与变更映射边界增加工作。独立回退对应入口及共同接口的兼容部分，保留回归测试；不批量改写用户文档或清理资产。
