# WP08 性能测量：发布构建与正确性联检

状态：2026-09-08，主负责人设计。尚未采集发布基线，不代表任何性能预算已获批准。实现脚本、夹具和探针仍由 `luna_coder / gpt-5.6-luna / max` 完成。

## 运行隔离与构建标识

复用原生证据启动器的独立配置、笔记目录、WebView2 profile、随机应用标识和进程所有权检查。脚本必须启动并识别自己创建的进程；不得通过端口扫描挑选任意活动 LightMark 页面。写入路径必须属于当前测试根目录。记录启动失败、断言失败与清理结果，保留原始材料。

最终基线使用固定 Rust release 与 Vite production 构建。记录 HEAD、未提交补丁摘要、实际参与构建的源码清单及 SHA-256、exe 与前端资源哈希、编译参数、是否启用 QA bridge。HEAD 加“工作区有修改”不足以标识构建。构建期间核心模块停止写入；完成后记录构建物哈希，运行不再依赖 Vite HMR。

测试机记录 OS build、CPU、物理内存、WebView2/Node/Rust 版本、实际视口与设备像素比、供电模式与前台/后台状态；无法读取的字段写未知。独立 profile 的首次运行与重复启动分别记录。这里的“冷启动”指新应用进程与新 profile 的首次启动，不声称清空 Windows 文件缓存；“热启动”指同一隔离 profile 下退出后重新启动。另行记录同一进程内首次打开和再次打开文档，不能混入启动样本。

## 夹具集合

六类负载：普通写作、大文档、公式密集、表格密集、图片密集、长行。夹具只引用测试目录内的固定本地资源；记录 UTF-8 字节数、UTF-16 长度、行数、块数、公式/表格/图片数、最大行长与文件及资源哈希。图片资源与渲染尺寸、压缩格式必须固定，不能以远程资源延迟当作编辑器性能。

独立加入恰好 `5 MiB - 1`、`5 MiB`、`5 MiB + 1` 的 UTF-8 文件，确认实际选择的文档模式，再运行适用交互。填充不得截断多字节字符。普通与大文件分块模式的编辑能力不同，不直接合并其指标；不支持的交互标记“不适用”，同时验证产品反馈。

每个编辑负载包含可精确核对的操作区与不应变化的哨兵区。公式、表格、图片和长行不只用一个综合夹具代替。首轮规模由实际可运行性与任务需求确定，并公开数值；不能为了通过临时缩小失败负载而不报告。

## 计时口径

- 启动：外部进程启动请求到窗口/应用就绪信号分别记录；就绪需证明目标编辑区可接受操作。两者不能统称第一像素。
- 打开：发起产品打开操作到指定路径、文档模式、目标内容和可操作编辑区就绪。原生文件读取与前端准备分项有探针时另报。
- 输入：保留事件派发、模型接受、DOM 更新、下一次 rAF 与下一次呈现可观察边界的独立时间。`execCommand` 或 CDP 同步返回耗时只能称调用耗时；两个 rAF 不能冒充物理显示延迟。可用 Chromium trace 呈现事件时记录其名称与关联方法，否则明确呈现端未测。
- 粘贴、模式切换和公式提交：计时到实际版本与 DOM 就绪；不依赖任意固定等待秒数作为完成。错误、超时、保持 pending 或内容不符的操作为失败样本，不能静默剔除。
- 滚动：固定起止位置与距离，记录帧间隔、长任务和实际到达的内容位置。固定缩放与窗口尺寸。
- 内存：分开记录 JS heap 与应用/WebView2 进程内存；明确是否包含子进程。正常基线不手动强制 GC；有 GC 对照时单列。重复打开、编辑、切模式、关闭后检查增长与释放。

每种启动先采 10 次。交互每种负载至少 3 轮、每轮 100 次独立操作；预热与恢复夹具不纳入正式样本。保留逐操作数据、轮次、起始状态、结束状态和失败原因，报告每轮及总体中位数、P95、最大值、样本数。输入与删除、头部与尾部、两种模式不能混成一个分位数。样本不足或大量失败时不宣布稳定 P99。

## 正确性与测量成本

计时区间之外核对 Markdown 字节/语法范围、逻辑选区、DOM 焦点、dirty、历史和保存版本。每轮至少恢复原文并核对哈希，抽取中间操作逐步核对；不只看插入后删除总长度相等。发现内容错写、选区偏移或撤销丢失时，该负载的性能结果标为正确性失败，不能接受它的速度收益。

主基线不启用每键全文快照或验证器。为测量真实性可使用探针对照构建，但必须标识其额外成本，并至少做同夹具无探针的产品操作对照。测试 bridge 默认编译关闭；正常构建不得暴露任意文件写入或任意活动文档控制入口。

现有 `webview-performance-qa.mjs` 的同步 `execCommand` 分位数、默认 16ms 断言与任意活动页接入方式不能直接用于本次发布判定。新入口应保留有效夹具/算法验证，替换不可信的计时和连接边界，不能靠删除失败断言宣布通过。

基于实测波动、可见任务停顿和瓶颈提出预算，主负责人审查后再交用户确认。具体优化另拆工作包，不与测量或正确性修复混在一个补丁内。
