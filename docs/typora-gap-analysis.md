# LightMark vs Typora 剩余差距清单

> 更新时间：2026-06-22

本文档只保留 LightMark 当前仍未完整支持、或还明显弱于 Typora 的能力。已经落地的功能不再作为 gap 追踪，例如：查找替换面板、设置界面、导出 PDF/HTML/PNG/Pandoc 多格式、GitHub 风格警示框、内联/块级 HTML、代码块语言控件、图片粘贴/拖入、Mermaid/公式导出、主题切换与原生窗口适配、自动保存与崩溃草稿恢复、多文档标签页基础工作流。

---

## 一、P0：影响日常写作可靠性的缺口

### 1.1 文件外部变更与冲突检测

| ✓ | 任务 | 说明 |
|---|------|------|
| | 外部变更监听 | 文件被其他程序修改时提示重载或对比 |
| | 冲突检测 | 本地有未保存修改且磁盘文件变化时，提供保留本地、载入磁盘、另存为等选择 |

## 下一步建议

下一步优先级最高的是 **文件外部变更监听与冲突检测**。

理由：

1. 自动保存和多标签已经降低了“应用崩溃丢文档”的风险，但真实写作中还会遇到 Git、同步盘、外部编辑器改动同一文件的问题。
2. 这项能力是后续多窗口、跨设备同步、Git 集成的基础；如果没有文件时间戳和冲突策略，多文档越强，误覆盖风险越高。
3. 实现路径清晰：保存前记录快照，前端监听文件变更事件，冲突时提供重载、保留本地、另存为三种安全出口。

建议第一阶段只做：

| ✓ | 任务 | 说明 |
|---|------|------|
| | 文件快照 | 打开/保存时记录 `mtime`、文件大小和内容 hash |
| | 保存前冲突检测 | 当前磁盘快照变了且文档有本地修改时阻止直接覆盖 |
| | 外部变更提示 | 文件在外部修改时显示非阻塞提示，可选择重载 |
| | 删除/移动提示 | 文件路径失效时给出另存为或从标签关闭的选择 |
| | 安全写入 | 写入临时文件后原子替换，减少保存中断造成的损坏 |
