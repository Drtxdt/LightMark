# LightMark vs Typora 功能差距分析

> 更新时间：2026-05-23

本文档系统对比 LightMark 与 Typora 的功能差异，明确 LightMark 已实现与未实现的功能，并给出优先级建议。

---

## 十、差距总结与优先级

### P0 — 影响日常可用性（建议优先实现）

| 序号 | 功能 | 理由 |
|---|---|---|
| 1 | **查找替换 (Ctrl+F/H)** | 文本编辑器最基本功能，没有它无法用于正式写作 |
| 2 | **任务列表 `- [ ]`** | Markdown 最高频语法之一，笔记和任务管理的基础 |
| 3 | **删除线 + 高亮** | 常用格式标记，缺失明显 |
| 4 | **自动保存** | 防止数据丢失的用户基本预期 |
| 5 | **自动配对补全** | 输入括号/引号/反引号的基本体验 |
| 6 | **多标签页** | 实践中同时编辑多个文档是常态 |

### P1 — 显著提升体验（建议第二批次）

| 序号 | 功能 | 理由 |
|---|---|---|
| 7 | **Focus Mode / Typewriter Mode** | Typora 的标志性体验，差异化竞争点 |
| 8 | **PDF 导出** | 用户最高频的导出需求 |
| 9 | **图片拖拽/粘贴/尺寸调整** | 插入图片是刚需，当前只能通过路径引用 |
| 10 | **脚注 + 上下标** | 学术/技术写作常用 |
| 11 | **大纲跟随滚动 + H4-H6** | 文档导航体验的核心 |
| 12 | **YAML Front Matter** | Obsidian 生态兼容，文档元数据 |
| 13 | **Emoji 自动补全** | 笔记场景的轻松体验 |
| 14 | **右键上下文菜单** | 桌面应用的基本交互范式 |

| 序号 | 功能 | 理由 |
|---|---|---|

| 16 | **设置面板 UI** | 降低用户配置门槛 |

## 附：LightMark 对比 Typora 的差异化优势

LightMark 在以下方面已经优于 Typora 或具有天然优势：

1. **性能**：Tauri（Rust 原生）vs Electron（Chromium），启动速度和内存占用有数量级优势。
2. **数学公式编辑**：行内/块公式的实时 KaTeX 预览 + 点击编辑体验，Typora 仅支持渲染不支持编辑预览。
3. **Mermaid 图表编辑**：实时 SVG 预览 + 编辑，Typora 仅支持渲染。
4. **命令面板 (Ctrl+Shift+P)**：类似 VSCode 的无鼠标操作入口，Typora 没有此功能。
5. **插件系统**：从零设计了插件接口，Typora 的扩展能力较弱。
6. **安装包体积**：Tauri 打包产物远小于 Electron。

遗漏的语法细节：
  - 列表自动续行：当前行尾回车后是否自动创建下一个列表项？空列表项回车是否退出列表？
  - 有序列表自动编号：输入 3.  是否自动从 3 开始编号，还是始终从 1 开始？
  - 引用块嵌套：> > 双重引用 是否支持？
  - 代码块行号：围栏代码块内显示行号

  遗漏的交互细节：
  - 代码块复制按钮：鼠标悬停代码块时显示复制按钮（Typora 有）
  - 代码块语言标签：代码块左上角显示当前语言（如 javascript）
  - 选中文字字数统计：状态栏显示"已选中 X 字 / 共 Y 字"
  - 阅读时长估算：基于总字数估算阅读时间
  - 表格右键菜单：插入/删除行/列、设置对齐、排序
  - CSV 粘贴为表格：粘贴 CSV 数据自动创建表格
  - 滚动位置恢复：重新打开文件时恢复上次滚动位置
  - 前后导航：跳转后可以前进/后退到上一个位置
