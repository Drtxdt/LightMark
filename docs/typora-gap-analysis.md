# LightMark vs Typora 功能差距与改进清单

> 更新时间：2026-06-12

本文档列出 LightMark 相比 Typora 尚未实现的功能，按优先级拆解为可执行的小任务。每个任务前有复选框供追踪进度。

---

## 一、编辑器交互体验

### 1.1 查找与替换

| ✓ | 任务 | 说明 |
|---|------|------|
| | 查找功能 (Ctrl+F) | 在当前文档内搜索文本，高亮所有匹配项 |
| | 替换功能 (Ctrl+H) | 逐项替换或一键全部替换 |
| | 正则表达式查找 | 支持正则语法进行高级搜索 |
| | 跨文件全局搜索 | 在工作区所有 .md 文件中搜索 |

### 1.2 编辑体验

| ✓ | 任务 | 说明 |

## 十一、LightMark 差异化潜力

以下方向并非追赶 Typora，而是 LightMark 可以超越 Typora 的潜在优势：

| ✓ | 方向 | 说明 |
|---|------|------|
| | 命令面板增强 | 已有 Ctrl+Shift+P，可扩展为支持自定义命令、脚本执行 |
| | LaTeX 编辑体验深化 | 已有自动补全领先 Typora，可进一步做公式实时预览编辑面板 |
| | Mermaid 实时编辑 | 已有实时预览，可增加模板库、拖拽式图表构建 |
| | 大文件优化 | 已有虚拟滚动，可进一步做分块懒加载、增量解析 |
| | 插件生态 | 从零设计的插件接口，长期可形成社区生态（Typora 无此能力） |
| | 性能护城河 | Tauri vs Electron 的启动速度、内存占用差距本身就是持续优势 |
| | Git 集成 | 内置 Git diff、历史版本对比、提交（Obsidian 有插件，Typora 无） |
| | 双向链接 `[[]]` | Obsidian 风格的双向链接与知识图谱 |
| | 标签系统 | 文档级标签（Front Matter 已支持），全局标签聚合视图 |
| | 移动端适配 | Tauri 2 支持 iOS/Android，长期可覆盖移动端 |

## 十三、创新功能脑暴

以下方向并非追赶 Typora 或 Obsidian，而是在它们尚未做好的领域建立 LightMark 的独有竞争力。

### 13.1 文档内嵌与交互

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **内容块嵌入（Transclusion）** | 用 `![[doc#section]]` 语法将其他文档的某个章节实时嵌入当前文档，呈现为只读渲染块，源文更新后嵌入处同步刷新 |
| | **自定义渲染卡片** | 扩展 Markdown 链接语法，为特定 URL 模式渲染富交互卡片：YouTube 视频预览、GitHub 仓库卡片、CodePen 嵌入、天气/股票小部件。底层存为纯文本 `[card](url)`，渲染层负责 fetch 和展示 |
| | **内联变量与公式** | 在文档 Front Matter 中定义变量（如 `price: 99`），正文中用 `{{price}}` 引用，修改变量值后全文同步更新。可结合数学公式做动态计算 |
| | **数据表格增强** | 表格单元格内支持简单的公式计算（SUM/AVG/COUNT），类似迷你电子表格。数据排序、过滤（类似 Typora 但更深入） |
| | **标签折叠/展开** | 用 `<!-- fold-start -->` / `<!-- fold-end -->` 标记可折叠区块，阅读时折叠细节，写作时展开编辑 |

### 13.2 写作辅助与生产力

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **写作统计仪表盘** | 超越基础字数统计：词汇多样性（类符/形符比）、句长分布直方图、写作速度趋势（字/分钟）、每日写作热力图。类似 GitHub 贡献图但用于写作习惯追踪 |
| | **写作冲刺模式（Pomodoro）** | 设定目标字数和倒计时（如 25 分钟写 500 字），编辑器中央显示进度环和计时器，到时自动停笔提示。适配 NaNoWriMo 等写作挑战场景 |
| | **可读性分析面板** | 集成 Flesch-Kincaid、迷雾指数等可读性评分。高亮过长句子、被动语态、副词滥用、重复用词。类似 Hemingway Editor 但内置于 Markdown 编辑器中 |
| | **中文写作优化** | 中英文之间自动插入空格（盘古之白）、中英文标点规范化、术语一致性检查（如"插件"vs"扩展"统一）。这是 Typora 和 Obsidian 都没做好的中文场景 |
| | **片段系统（Snippets）** | 类似 VS Code 的代码片段但用于写作：输入 `/table` 弹出表格模板，`/warning` 插入 GitHub 警示框，`/toc` 插入目录。支持自定义片段和 `$1` `$2` 占位符跳转 |

### 13.3 视图与呈现

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **演示模式（Slide Deck）** | 一键将 Markdown 文档（以 `---` 分页）渲染为全屏演示文稿，类似 Reveal.js 但更轻量。支持演讲者备注（`<!-- note -->`）、渐入动画、主题切换 |
| | **思维导图视图** | 基于文档标题层级自动生成思维导图。不是替代大纲面板，而是另一种可视化导航方式。节点可拖拽重组，修改后反向更新文档结构 |
| | **看板视图** | 将文档中的任务列表 `- [ ]` 切换为看板视图（Todo / Doing / Done），按二级标题分组。拖拽卡片改变状态，底层同步修改 `[ ]` → `[x]` |
| | **时间线视图** | 对含有日期字段（Front Matter 中的 `date` / `created` / `updated`）的文档集合生成时间线，适合日记、周报、项目日志场景 |
| | **分屏对比模式** | 并排显示两个文档或同一文档的两个版本，同步滚动。用于翻译对照、版本对比、参考写作 |
| | **Zen 模式增强** | 不仅是全屏，还包括：柔和的打字音效（可关闭）、段落级淡入动画、当前行柔和高亮、背景虚化。打造沉浸式写作氛围 |

### 13.4 知识管理

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **智能标签系统** | 从 Front Matter 读取标签 + 从正文自动建议标签（基于 TF-IDF 关键词提取）。全局标签面板展示所有标签及其关联文档数。标签颜色/图标自定义 |
| | **保存的搜索（智能文件夹）** | 将搜索条件保存为虚拟文件夹：如 `tag:rust AND tag:tutorial`。点击智能文件夹时实时查询匹配的文档列表 |
| | **每日笔记 + 日历视图** | 一键创建/打开今日笔记（文件名 `2026-06-12.md`，模板可自定义）。侧边栏日历小部件显示有笔记的日期（类似 Obsidian Daily Notes 但更轻量） |
| | **间隔重复 / 闪卡模式** | 识别 Markdown 中的问答模式（如 `## Q: ...\n\nA: ...`），生成闪卡。内置 SRS 算法（SM-2），按记忆曲线提醒复习。导出为 Anki 兼容格式 |
| | **双向链接面板** | 在文档底部或侧边栏显示"链接到本文档的页面"和"本文档引用的页面"，形成微型知识图谱。悬停预览被引用文档的内容 |

### 13.5 版本与历史

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **文档快照与可视化 Diff** | 手动或自动创建文档快照（存在 `.lightmark/snapshots/`）。任意两个快照之间做 prose-aware 的 diff（按段落/句子对齐，而非逐行），渲染为带高亮的对比视图 |
| | **写作历史回放** | 记录每次保存的编辑操作，可以像视频回放一样逐帧回放文档的写作过程。用于回顾创作思路或教学演示 |
| | **建议模式（Suggestion Mode）** | 类似 Word 的修订模式：修改以标记形式显示（删除线 + 颜色标记），可逐条接受/拒绝。对于多人共用文档或审稿场景非常实用 |

### 13.6 集成与发布

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **一键发布到 Web** | 将当前文档发布为在线页面：生成静态 HTML → 推送到 GitHub Pages / Vercel / Cloudflare Pages → 返回公开链接。需要配置一次部署令牌 |
| | **浏览器剪藏伴侣** | 配套浏览器扩展（或 bookmarklet）：一键将当前网页转为干净 Markdown 并通过本地 HTTP 端点发送到 LightMark 中打开。解决从网页收集素材的痛点 |
| | **命令行入口（CLI）** | `lightmark open note.md` 在已运行的实例中打开文件；`lightmark export note.md --pdf` 无头导出；`lightmark serve ./docs` 启动本地预览服务器。打通终端与 GUI 工作流 |
| | **自动化规则引擎** | 用户定义"当 X 时自动做 Y"规则，例如：当图片粘贴时自动压缩 >1MB 的 PNG → 保存前自动备份到 `.lightmark/backups/` → 新建文档时自动从模板填充。事件驱动的轻量自动化 |

### 13.7 协作（远期）

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **本地优先 CRDT 协作** | 无需服务器：两台设备通过局域网或 Tailscale 直连，基于 Yjs/CRDT 实时协作编辑同一文档。本地优先意味着断网也能编辑，恢复连接后自动合并 |
| | **评论/批注系统** | 选中文本后添加评论（存为 Front Matter 或独立的 `.comments.json`），评论锚定到段落 hash，不污染 Markdown 正文。审稿和团队协作的基础设施 |
| | **文档共享与权限** | 生成带有可选密码和过期时间的只读分享链接（需要简单的内置 HTTP 服务或 P2P 连接）。适合临时分享草稿给外部审阅者 |

### 13.8 编辑器核心技术储备

| ✓ | 创新点 | 说明 |
|---|--------|------|
| | **多光标 / 多点编辑** | 在所见即所得模式下支持 Alt+Click 放置多个光标，同时编辑多处。借助 ProseMirror 的 State 模型可实现 |
| | **所见即所得 + 源码双联模式** | 左右分屏：左侧 WYSIWYG，右侧实时同步的 Markdown 源码（非源码编辑模式，而是镜像预览）。编辑任意一侧，另一侧实时更新 |
| | **LSP 风格的 Markdown 诊断** | 在编辑器中实时标记：断开的链接 `[text](missing.md)`、引用不存在的脚注、图片路径无效、Front Matter 格式错误。黄色波浪线警告，红色波浪线报错 |
| | **AST 级别的查找替换** | 查找替换不仅匹配文本，还能匹配语义：如"查找所有 H2 标题中的关键词"、"查找所有链接 URL 包含 github.com 的链接"、"替换所有图片的对齐属性" |

## 附：建议的下一阶段聚焦

如果追求"用最小代价实现最大差异化"，建议优先攻克以下 3 个方向：

1. **中文写作优化** — 极低成本，所有中文用户立刻能感知到诚意
2. **演示模式 + 看板视图** — 两个"哇塞"功能，演示和项目管理的杀手场景，Typora 完全没有
3. **片段系统** — 降低写作摩擦，`/` 触发的 slash command 是现代编辑器的标配体验
